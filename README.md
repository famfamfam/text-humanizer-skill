# Text Humanizer

Версия 1.1.2. Ранее скилл назывался Humanizer.

Russian and English prose editing for Claude, Codex, and Hermes.

Скилл помогает сделать текст яснее и естественнее, сохраняя факты, степень
уверенности и голос автора. Работает с русским и английским: общее ядро задаёт
правила редактуры, языковые заметки подключаются по необходимости.

Подходит для писем, постов, статей, инструкций и сценариев. Может отредактировать
черновик, дать замечания или написать текст по брифу. Не определяет авторство
текста и не обещает обход AI-детекторов.

## Что он бережёт

- Числа, сроки, условия, отрицания и оговорки: «может» не превращается в «будет».
- Атрибуцию: неизвестный исполнитель не становится «мы».
- Цитаты, ссылки, код и подстановки вроде `{{name}}`.
- Жанр: деловое письмо не превращается в фамильярный пост.
- Язык и его вариант: русский остаётся русским, British English — британским.
- Хороший текст: если правка не нужна, скилл может оставить его как есть.

Внешние инструменты, API-ключи и библиотеки для работы скилла не нужны.
Инструкции написаны на английском, русские рекомендации — на русском.
Язык инструкций не задаёт язык результата.

## Установка

Одна папка `text-humanizer` используется во всех клиентах. В ней должны оставаться
`SKILL.md`, `references/` и `LICENSE`. Имя репозитория — `text-humanizer-skill`,
имя устанавливаемого скилла и его папки — `text-humanizer`.

| Клиент | Каталог для личной установки | Явный вызов |
| --- | --- | --- |
| Claude Code | `~/.claude/skills/text-humanizer/` | `/text-humanizer` |
| Codex | `~/.agents/skills/text-humanizer/` | `$text-humanizer` в CLI/IDE; выбор скилла в приложении |
| Hermes Agent | `~/.hermes/skills/text-humanizer/` | `/text-humanizer` |

Это стандартные пользовательские каталоги. Для отдельного профиля Hermes
используй каталог skills этого профиля. Устанавливай скилл в той среде, где
работает агент: например, внутри WSL, если агент запущен в WSL.

### Через Git

Нужен установленный Git. Выбери команду для своего клиента.

**macOS / Linux / WSL:**

```bash
# Claude Code
git clone https://github.com/famfamfam/text-humanizer-skill.git ~/.claude/skills/text-humanizer

# Codex
git clone https://github.com/famfamfam/text-humanizer-skill.git ~/.agents/skills/text-humanizer

# Hermes Agent
git clone https://github.com/famfamfam/text-humanizer-skill.git ~/.hermes/skills/text-humanizer
```

**Windows PowerShell:**

```powershell
# Claude Code
git clone https://github.com/famfamfam/text-humanizer-skill.git (Join-Path $HOME '.claude/skills/text-humanizer')

# Codex
git clone https://github.com/famfamfam/text-humanizer-skill.git (Join-Path $HOME '.agents/skills/text-humanizer')

# Hermes Agent
git clone https://github.com/famfamfam/text-humanizer-skill.git (Join-Path $HOME '.hermes/skills/text-humanizer')
```

Если папка уже существует, не клонируй поверх неё. Для обновления установленной
Git-копии выполни `git pull --ff-only` из папки скилла; локальные изменения
сначала сохрани. Если клиент не показывает скилл, начни новую сессию.

При обновлении с версии 1.0.0 переименуй установленную папку `humanizer` в
`text-humanizer` после обновления файлов. Новый вызов — `/text-humanizer`
или `$text-humanizer`. Если ставишь новую копию рядом со старой, удали или отключи
старую установку, чтобы клиент не показывал два скилла.

### Без Git и для Claude.ai

Скачай [text-humanizer.zip из последнего релиза](https://github.com/famfamfam/text-humanizer-skill/releases/latest/download/text-humanizer.zip).
Для локального агента распакуй папку `text-humanizer` в его каталог skills из таблицы.

В Claude.ai загрузи этот ZIP через управление пользовательскими Skills и включи
скилл. Доступность загрузки зависит от возможностей аккаунта; см.
[официальную инструкцию Claude](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview#claudeai).
Установка в локальный Claude Code и загрузка в Claude.ai — отдельные способы.

## Использование

Вызови `/text-humanizer` в Claude Code или Hermes, либо `$text-humanizer` в Codex,
и добавь задачу с текстом. Можно попросить обычными словами — автоматический
выбор зависит от клиента и модели.

В пакетном режиме Hermes используй `hermes chat -s text-humanizer -q "..."`.
В проверенном одиночном режиме `-q` модель пропустила скилл в двух подходящих
запросах без явного вызова; полагаться на автоматический выбор в этом режиме
не стоит.

```text
Отредактируй письмо клиенту: спокойно, без канцелярита.
Сохрани срок и обращение на «вы».

Просим вас осуществить отправку подписанного акта до 18 сентября.
```

Возможный результат:

> Пришлите подписанный акт до 18 сентября.

```text
Make this email sound natural. Keep British English and the deadline.

We would like to request that you send the signed form by 18 September.
```

Возможный результат:

> Please send the signed form by 18 September.

Можно задать аудиторию, тон, длину, образец голоса или запрет на перестройку
структуры. По умолчанию скилл возвращает готовый текст без отчёта о правках.
Если нужны только замечания или объяснение изменений, скажи об этом.

Скилл сохраняет язык исходника, включая намеренное смешение RU/EN.
Перевод выполняется только по явной просьбе. Для нового текста нужен бриф;
неизвестные факты скилл не должен придумывать.

## Проверка качества

В [evals/cases.md](evals/cases.md) есть 15 сценариев (16 запросов) и проверки выбора скилла:
оговорки и отрицания, неизвестный исполнитель, цитаты, смешение языков,
официальный регистр, отсутствие исходника и ограничение длины.

Это воспроизводимый план ручной проверки. Наличие набора не означает, что все
сценарии прогнаны во всех клиентах. Разные модели могут следовать инструкциям
по-разному; перед использованием на важных текстах проверь их на своих примерах.

[Актуальные результаты 1.1.2](evals/results-1.1.2.md): модельный прогон Hermes
завершён после отдельного входа. Из 16 явных запросов 15 прошли сразу; неточный
разбор в оставшемся запросе исправлен и перепроверен в Hermes, Claude и Codex.
Статья на русском — 360 слов, сценарий на английском — 190 слов, оба в заданных
пределах. Автовыбор Hermes дал 3/5: два подходящих запроса выполнены без загрузки
скилла. Это известное ограничение одиночного режима, а не пройденные проверки.

Приписки Codex вызывал активный Ponytail; для изолированных тестов используется
`PONYTAIL_DEFAULT_MODE=off`. Параметр задаётся только тестовым процессам.
В [отчёте 1.1.1](evals/results-1.1.1.md) сохранены завершённые проверки Codex
и Claude: прежние ограничения аккаунта сняты, потеря стадии действия исправлена.
Прогоны дополняют друг друга; это не полная матрица всех клиентов и моделей
на одной версии. Подробности окружения и подтверждение загрузки — в отчётах.

В 1.1.2 уточнена точность замечаний при разборе текста. Правило 1.1.1 о стадии
действия сохранено: решение что-то сделать не превращается в завершённое действие.
Исторические отчёты [1.0.0](evals/results-2026-10-23.md) и
[1.1.0](evals/results-1.1.0.md) описывают прошлое состояние, включая старые лимиты.
